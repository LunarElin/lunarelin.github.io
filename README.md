# LunarElin — Game Client Developer

게임 클라이언트 개발자 정우용(LunarElin)의 포트폴리오입니다. 노션 원문을 바탕으로 Ark, 그랑사가·GSU, 세븐나이츠 글로벌 등의 담당 업무와 기술 스택, 협업 방식을 소개합니다. 2026년 10월 21일 사용자가 확인한 파이드픽셀즈 재직 경력(2025.09.01–현재)을 추가했습니다. 기존 문서의 약 16년 3개월에 새 재직 기간을 더해 총 경력은 17년 이상으로 표현하며, 새 회사의 직급·엔진·출시 성과는 추정하지 않습니다.

에이전트는 작업 전에 [AGENTS.md](AGENTS.md)의 저장소 지도, 작업별 진입점, 검증 명령과 Git 작업 규칙을 참고합니다.

## 구성

- `index.html`: 프로토타입 우선의 포트폴리오 메인, 대표 사례와 경력·소개
- `portfolio/block-bloom.html`: 블록 블룸의 설계 의도·Codex 협업·검증 근거와 후속 검증 제안
- `portfolio/case-study.css`: 대표 사례 페이지 디자인
- `portfolio/style.css`: 포트폴리오 디자인
- `portfolio/main.js`: 현재 읽는 영역의 메뉴 강조
- `portfolio/mark.svg`: 직접 작성한 달·별 파비콘
- `archive/2026-10-14-original/index.html`: 전환 전 원본 페이지

빌드나 패키지 설치 없이 정적 HTTP 서버 또는 GitHub Pages에서 실행합니다.

경력·자기소개의 출처는 [기존 노션 포트폴리오](https://app.notion.com/p/23aeae97f1a2800eb4d8e161e8e464bd)입니다. 사용자가 제공한 비공개 이력서에서 성명·이메일·학력·병역만 반영했으며 주소·전화번호와 원문 전체는 저장하지 않습니다. 파이드픽셀즈 업무는 사용자가 직접 설명한 일본 IP 횡스크롤 액션, 영웅·몬스터 AI 클라이언트 전투, ATB 턴제 결투장 작업으로 한정합니다.

이동 동기화 기술은 사용자가 확인한 이동 패킷 수신·중간 보간·이동/점프 시뮬레이션·RecastNav 활용과 노션 기술 메모를 근거로 요약했습니다. 용어는 이동 보간(Interpolation)·네트워크 스무딩(Network Smoothing)으로 표현합니다. 구체 구현이 확인되지 않은 스냅샷 버퍼링, 데드 레코닝, 자기 입력 예측·서버 재조정은 경력으로 단정하지 않으며, 내부 경로·프로젝트 코드·비공개 기술 문서 원문은 공개하지 않습니다.

`portfolio/assets/`의 이전 게임 이미지 5개는 기존 노션 포트폴리오의 첨부 이미지를 WebP로 무손실 변환해 로컬로 제공합니다. 원문에 연결된 [슈퍼빌런랩스 AMA](https://www.youtube.com/live/hHAhYbN0tQI), [GSU 레이드](https://youtu.be/sRqXcnXf2oI), [그랑사가 결투장](https://youtu.be/Ji5BV7GBIME)의 영상 썸네일 3개도 로컬로 제공합니다. 연보라색과 경력 이미지 갤러리를 유지하고, 자기소개에는 현재 개발 업무를 보강했습니다.

게임 프로토타입과 블록 블룸 대표 사례를 먼저 보여주는 구성은 [베이글코드 AI Game Director 공고](https://career.bagelcode.com/ko/o/212948)의 코어 설계·AI 프로토타이핑·검증 관점을 참고했습니다. 대표 사례의 구현 설명은 게임 README·제작 노트·소스를 근거로 하며, AI 협업은 실제 Codex 제작 요청·명령 실행·검사 출력·배포 기록을 확인해 정리했습니다. 제작자가 정한 방향과 Codex의 구현·검증을 구분하고, 사용자·UA·매출 성과는 추정하지 않습니다. 초기 구현은 [커밋 24ffd68](https://github.com/LunarElin/lunarelin.github.io/tree/24ffd68a087d7e680191302bcf99f07c9b1241d2/games/block-bloom)에서 확인할 수 있습니다.

2026년 10월 29일에는 등록된 웹 게임 8개를 대표 사례와 최근 제작 게임 순으로 정리하고, 숲의 수호자·룬빛 상회의 실제 실행 화면과 설계·개선 기록 링크를 추가했습니다. 숲의 수호자는 현재 필드·거점·장비 성장과 자동 기술의 구현 범위를 소개하며 미구현 변신을 완료 기능으로 기재하지 않습니다. 룬빛 상회는 단색 그래픽과 화면 밀도·전투 구도 개선을 기록된 범위에서 설명합니다. 에이전트의 브라우저 관찰·자동 검사와 외부 이용자 검증은 구분합니다.

`block-bloom-campaign-screen.webp`·`block-bloom-campaign-board.webp`는 2026년 10월 29일 현재 실행본의 첫 판 실습 화면과 보드 크롭입니다. 대표 사례는 1~7판 학습·8~12판 조합·13판 이후 응용, 제작자의 수정 요청과 구현·검토 기록을 근거로 갱신했습니다. `grove-warden-scene.webp`는 로컬 저장 진도의 현재 필드 화면, `runehaven-scene.webp`는 정상 규칙으로 진행을 재현하는 `?qa=1&scenario=late-defense` 검증 시나리오의 상점 화면 크롭입니다. 이 이미지를 이번 작업에서 사람이 후반까지 완주한 증거로 사용하지 않습니다.

기존 `block-bloom-screen.webp`와 `block-bloom-board.webp`는 2026년 10월 18일 초기 모드형 화면으로 보관합니다. 홈페이지는 게임 코드와 자산을 실행하지 않고 압축한 결과 화면만 제공합니다.

첫 화면 이미지 외의 이미지는 지연 로딩하며, 영상은 클릭 시 YouTube로 이동합니다. 외부 글꼴·게임 코드·영상 플레이어는 홈페이지에서 미리 로드하지 않습니다. 본문은 운영체제의 한글 지원 글꼴을 사용합니다.

홈페이지 수정 후 `node --check portfolio/main.js`와 `git diff --check -- index.html portfolio README.md`를 실행하고, 실제 브라우저에서 320px·390px·PC 배치와 세부 경력 펼치기, 게임 진입·홈 복귀를 확인합니다.

## 게임 추가와 관리

게임은 각각 `games/<slug>/` 안에서 독립 실행·관리합니다. 공개 게임 목록은 홈페이지 `index.html`의 게임 영역에서 관리하고, 각 게임의 설명·규칙·실행·검증·저장 정책은 해당 폴더의 `README.md`에 둡니다.

새 게임을 추가할 때는 독립 폴더 생성 → 게임과 README 작성 → 홈페이지에 플레이 링크 등록 → 대상 게임과 이동 경로 검증 순서로 진행합니다. 공통 [작업 안내](AGENTS.md)에는 게임별 목록을 추가하지 않습니다.

게임 수가 늘어나도 검색·의존성 설치·테스트는 작업 대상 폴더로 한정합니다. 홈페이지에서는 게임 코드나 대용량 리소스를 미리 실행·로드하지 않고, 실제 공통 코드 변경 시에만 영향을 받는 게임으로 검증 범위를 넓힙니다.
