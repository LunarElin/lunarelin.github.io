## 이번 변경과 결함 수정

- 모드 선택 화면을 제거하고 1~12의 기믹 도입·조합 순서를 제공합니다. 13부터는 8~12의 조합을 순환하며 난도를 높이고 `응용 기믹`으로 안내합니다. 매 판 새로운 고유 규칙이 무한히 생기는 시스템은 아닙니다.
- 결과 화면에 다음 기믹을 예고합니다. 다음 스테이지·재시작 전에는 그림·설명·팁을 확인한 뒤 `시작`을 누릅니다. 설명을 읽는 시간에는 보드·아이템·시계가 동작하지 않습니다. 다시 열기와 새로고침에서도 대기 상태를 보존합니다.
- 생성기와 승강기를 별도 단계로 도입했습니다. 조합 상태를 규칙·연속 드래그·출구·힌트·보드 표시에서 같은 방식으로 검사합니다. 합성 시 열쇠는 보존하고 얼음은 더 강한 겹수를 유지합니다.
- 구형 모드 저장은 `이어서 플레이`로 실제 기믹을 설명하고 기존 보드를 유지합니다. 기존 모드의 승리·레벨 수로 초반 수업을 건너뛰지 않습니다. 구형 진행 판을 마치면 캠페인 진도에 합류합니다. 되돌리기 시 새로 확인한 시작 상태가 취소되어 시계가 멈추지 않도록 했습니다.
- 클리어 연출의 600ms 대기 중 도움말·상점을 누르면 결과 예약이 취소되어 빈 보드에 남는 문제를 재현했습니다. 완료 상태에서는 결과 화면으로 즉시 연결하며 회귀 테스트를 추가했습니다.
- 320px 결과창에서 `2,925`가 두 줄로 갈라지는 현상을 실제 브라우저에서 확인했습니다. 점수를 넓은 첫 줄로 옮기고 이동·코인을 아래 두 칸에 표시했습니다.
- 기존 연속 드래그의 작은 이동·소수 좌표 충돌·모서리 접촉 해제·실제 출구 폭·합성 누름·취소·안착·되돌리기·자원 정리 동작을 유지하고 회귀 검증했습니다.

## 검증 구분

- **규칙·캠페인·연속 충돌·DOM:** `node --test games/block-bloom/rules.test.mjs games/block-bloom/tests/campaign.test.mjs games/block-bloom/tests/drag.test.mjs games/block-bloom/tests/ui.test.mjs` — 69개. 기본 1,200개 보드, 1~27스테이지의 1,260개 보드 전체 해답·시드 재현, 1~12의 힌트 종료, 조합의 열쇠·얼음·수집·이어하기를 검사합니다. DOM에서는 1~12를 실제 블록·방향 버튼으로 순차 완주하고 설명·다음 진도·저장·재시작·보상을 검사합니다.
- **실제 데스크톱 Chromium:** 고정 시드의 1스테이지를 아이템 없이 블록·방향 버튼 99회 이동으로 완주. 3별·130코인과 다음 열쇠 기믹 예고를 확인하고, 2스테이지 설명으로 이동·새로고침·시작·드래그·일시 정지·홈 복귀·게임 재진입을 확인했습니다. 이는 정답 경로를 사용하는 동작 확인이며 신규 사용자의 자발적 풀이·재미 평가가 아닙니다.
- **모바일 뷰포트:** 320×568에서 1~13의 안내를 검사했습니다. 시작 버튼은 항상 화면 안에 있고, 긴 설명만 창 내부에서 스크롤됩니다. 합성·생성기·승강기·빙결·열쇠·수집 조합의 게임 화면에 문서 스크롤·44px 미만 버튼·스테이지명 잘림이 없습니다. 보드 폭 268~270px. 390×667에서도 안내와 게임 배치를 확인했습니다.
- **PC와 크기 변경:** 1280×720에서 보드 폭 384px, 스테이지 숫자 34px, 문서 스크롤·잘림 없음. 390px로 변경할 때 블록의 좌표가 보존됩니다. 검사한 탭의 브라우저 오류·경고는 없었습니다.
- **이전 드래그 검증 근거:** 720개 보드·139,586개 입력의 보조 수치 검사, 692개 경로를 1·4·50회로 나눈 38,060개 입력의 일관성 검사 기록을 유지합니다. 작은 이동·장애물 옆 미끄러짐·안착은 이전 실제 Chromium 검증, 한 번 누른 채 여러 차례 꺾기·다중 포인터·합쳐진 표본·touch 포인터 타입은 DOM 이벤트 검증입니다. 이번 변경에서도 관련 회귀 테스트를 실행했습니다.
- **미검증:** 실제 휴대폰 Safari·Android Chrome, 노치·주소창의 실물 동작, 실제 손가락의 연속 경로, 진동·오디오 지연, 저사양 피버 FPS와 장시간 메모리, 다른 플레이어의 기믹 이해·재미·장기 난이도. 실제 결제·광고 SDK는 연결하지 않은 데모입니다.

## 다음 개선 우선순위

1. **실기기 호환:** iPhone Safari·Android Chrome에서 주소창·안전 영역·터치 취소·오디오 재개를 점검해 버튼 가림과 재생 실패를 줄입니다.
2. **기믹 학습과 난이도:** 첫 7판의 안내 이해·교착·힌트·부스터 소모를 사용자 플레이테스트로 측정하고 소개 순서와 보드 밀도를 조정합니다. 해답이 있다는 검사만으로 재미나 균형을 보장할 수 없습니다.
3. **저사양 연출:** 실제 기기의 피버 프레임·메모리를 측정하고 파편 수·블러·동시 음성 수를 조정합니다. 자원 상한과 정리 테스트를 FPS 보장으로 해석하지 않습니다.
