# 작은 머지 v1

실행: 저장소 루트에서 `python -m http.server 8765`, http://localhost:8765/games/merge3/ 접속.
공개 예정 주소: https://lunarelin.github.io/games/merge3/

## 규칙 / 재현 프롬프트

순수 HTML/CSS/JavaScript로 games/merge3/index.html에 모바일 5×5 퍼즐을 만든다.
초기 보드 0 기반 인덱스 10·11에 1, 다음 타일은 1. 빈칸에 배치한다.
상하좌우로 연결된 같은 숫자 3개 이상을 모두 소모하고 배치 칸에서 숫자 +1.
4개·분기 연결도 모두 소모하며 대각선은 제외한다. 같은 칸에서 연쇄를 반복한다.
머지 점수는 소모 타일 수 × 결과 숫자 × 10. 숫자는 단계 번호이며 3의 거듭제곱 표시값이 아니다.
다음 타일 생성은 1 80%, 2 20%. 모든 연쇄 후 빈칸이 없으면 종료한다.
무효 입력은 턴·다음 타일·점수를 변경하지 않는다. 동기 처리로 중복 이벤트 경로를 만들지 않는다.
첫 머지는 강조 칸(12)에 놓으면 성공. 안내는 첫 유효 입력 후 일반 안내로 전환한다.
다른 빈칸을 선택하면 안내를 건너뛰고 즉시 자유 플레이 가능. 새 판은 안내를 다시 표시한다.
외부 리소스 없이 실행, 저장소 오류에도 플레이 유지, 마우스·터치는 버튼 click 단일 경로.
새 판마다 버전·시드·설정을 고정하고 턴별 보드·경과 시간을 JSON으로 내려받는다.
최고 점수는 localStorage에 저장. 재시작은 보드·점수·턴·시드·로그 초기화.

## 검증 / 플레이테스트

기술 확인: 2개 무병합, 기본 3개, 대각선 제외, 4개 이상·분기,
연쇄, 무효 입력, 마지막 빈칸 병합, 꽉 찬 보드 종료, 재시작을 확인한다.
정확히 3개 소모 규칙이 아니므로 점유 변화는 `+1 - Σ(소모 수 - 1)`이다.
첫 머지까지 시간·입력 수, 판당 턴·시간, 연쇄·실패 보드는 로그에서 확인한다.
가설: 숫자 연결을 쉽게 이해하고 다음 배치에 고민이 생긴다.
사람의 플레이 관찰: 미수행. 직접 휴대폰에서 한 판 플레이하고
혼란·답답함·고민한 순간, 자발적으로 재도전하고 싶은 이유를 기록한다.
조건(v1, 시드), 관찰, 해석, 유지/수정/폐기 결정, 다음 실험을 남긴다.
재시작만으로 재미·리텐션을 판정하지 않는다. 다음 실험은 생성 분포 한 변수만 변경한다.
