# 룬빛 상회

대장간·잡화점·연금 공방·여관을 운영하는 모바일 웹 판타지 게임이다. 무기·물약과 주방 음식을 머리 위로 나르고 판매해 마법을 강화한다. 여관 손님은 배식대에서 음식을 받아 식탁에 앉아 먹으며, 사용한 식탁은 주인공이나 정리 담당 조수가 정리해 다시 쓴다. 조수에게 무기·물약·음식 운반과 식탁 정리 중 하나를 맡길 수 있다. 구매 손님은 전사에서 궁수·마법사로 늘어나며, 습격이 오면 돌아와 상회를 방어한다. 이동을 마지막까지 강화하면 짧은 순간이동을 사용한다.

## 실행과 파일

- 진입점: `index.html`
- 로컬 경로: `/games/runehaven/`
- 공개 배포 시 경로: `https://lunarelin.github.io/games/runehaven/`
- 홈 복귀: `../../`
- `game.mjs`: 브라우저 화면·입력·저장 연결
- `camera.mjs`: 짐 높이·화면 여백을 고려한 추적과 전투 구도
- `product-visuals.mjs`: 운반·진열품의 공유 geometry와 인스턴스 재사용
- `actor-markers.mjs`: 군중의 체력바·직업 링 일괄 렌더링
- `actor-appearance.mjs`: 공유 atlas를 사용하는 실제 인물 모델의 역할별 의상·후드 색상
- `rules.mjs`: 경제·성장·손님·조수·습격 시뮬레이션
- `battlefield.mjs`, `battlefield-visuals.mjs`: 실내와 분리한 야외 전투 좌표·상점 외벽과 마당
- `combat-motion.mjs`: 실제 손뼈에 붙는 무기와 타격 1회에 대응하는 단발 공격 모션
- `dining.mjs`: 여관 주방·배식대·식탁 배치와 음식·식사·정리 기준
- `dining-visuals.mjs`: 음식·식기·식탁·의자의 공유 입체 리소스
- `maps.mjs`, `map-scene.mjs`: 일반 지역 10곳의 배치·동선과 입체 지형·장식
- `balance.mjs`: 보존 수치와 새 웹게임 규칙의 경계
- `data/source-balance.mjs`: 실제 사용하는 선택 수치
- `data/provenance.json`, `data/PROVENANCE.md`: 원문 출처·해시·필드 매핑·재해석
- `DESIGN.md`: 제작 순서·완료 조건·후속 확장 구분
- [RESEARCH.md](./RESEARCH.md): 공식 원작 자료·직접 관찰·추론과 새 구현값의 구분

저장소 루트를 제공하는 기존 정적 서버를 우선 재사용한다. 새 서버가 필요하면 저장소 루트에서 다음과 같이 실행한다. Windows의 `.mjs` MIME 연결과 무관하게 모듈을 올바른 타입으로 제공한다.

```powershell
node games/runehaven/tests/serve.mjs
```

이 경우 `http://127.0.0.1:8765/games/runehaven/`로 접속한다. 디렉터리의 `index.html`과 `.mjs`의 JavaScript MIME 타입을 지원하는 서버가 필요하다. 게임 실행을 위한 루트 패키지 설치 과정은 없다. Three.js r170(0.170.0)의 `three.module.js`, `GLTFLoader`, `BufferGeometryUtils`, `SkeletonUtils`는 `vendor/`에 로컬로 제공하고 화면·입력은 일반 ES 모듈로 연결한다. 라이브러리·이미지·글꼴의 출처와 라이선스는 해당 로컬 라이선스 파일 및 `assets/SOURCES.md`에 기록한다.

## 조작과 핵심 규칙

휴대폰에서는 바닥·작업장 표식을 누르거나 화면 조이스틱으로 이동한다. 작업점 근처에서 0.4초 정지하면 0.22초 간격으로 물건을 하나씩 싣거나 내린다. 이동 중에는 상하차하지 않으며 운반물은 캐릭터 머리 위 스택으로 표시한다. 판매·식사 매출은 소지금에 바로 들어가지 않고 해당 가게의 현금 더미에 쌓인다. 더미에 0.9 이내로 접근하면 정지 대기 없이 직접 회수한다. 방어 승리 보상은 소지금에 바로 지급한다. 이 거리·시간은 원작 영상에서 추출한 상수가 아닌 새 웹게임 규칙이다.

무기·물약 진열 표식이나 해당 바닥을 누르면 진열대 중심의 `z−0.85`인 뒤쪽 납품 지점으로 이동해 손님 앞줄과 작업 동선을 분리한다. 공급 시설의 접근 지점은 `z+0.8`을 유지하고 직접 조이스틱으로 자유롭게 움직일 수도 있다. 이 접근 거리는 새 웹게임 값이며, `getStationApproach()`가 지역별 시설 좌표에 적용한다.

작업장·수금·식탁 표식과 바닥 탭은 목표까지 직선으로 이동하고 조수도 같은 작업점을 공유한다. 손님은 공통 입구 줄에서 순서대로 들어와 분기점을 지난 뒤 각 진열대의 짧은 줄로 향하며, 배식대·식탁·출구로는 바로 걷는다. 영업 중 인물 겹침은 허용하고 충돌 회피·조수 자리 분산·고객 밀어내기 계산을 사용하지 않는다. 전투의 기존 같은 편 분리 규칙은 유지한다.

판매 16회 뒤 개방할 수 있는 여관에는 주방·배식대와 식탁 4개가 있다. 음식은 주방에 3초마다 1그릇씩 자동 조리해 최대 8그릇까지 쌓인다. 주방의 초기 음식은 4그릇이고 배식대는 비어 있으며, 배식대에도 최대 8그릇까지 놓을 수 있다. 주인공이 주방 앞에서 멈춰 음식을 머리 위에 싣고, 배식대까지 직접 운반해 멈추면 하나씩 내린다. 무기·물약·음식은 같은 운반량을 나눠 쓰며 0.4초 정지 대기·0.22초 상하차 간격도 같다. 음식이 주방에서 배식대로 자동 전송되지는 않는다.

구매 손님의 60%가 최대 4명까지 배식 줄에 들어가고, 맨 앞 손님은 배식대 음식과 깨끗한 식탁이 모두 있을 때 1그릇을 받아 예약한 식탁으로 직선 이동해 앉아 먹는다. 식사 시간은 여관 단계에 따라 5 / 4.7 / 3.7초다. 식사가 끝나면 기존 여관 매출을 바닥 대금에 남기고 단골은 회복·충성도 1을 얻는다. 사용한 식탁은 `정리` 표식으로 바뀌며 주인공이 가까이 가서 1.2초 정지하거나 정리 담당 조수가 작업하면 다시 사용할 수 있다. 주인공이 이동하면 자신의 정리 진행이 초기화된다. 모든 식탁이 더러우면 음식이 있어도 새 손님은 배식대에서 기다린다.

고용 화면에서는 각 조수의 담당을 무기 운반·물약 운반·음식 운반·식탁 정리 중 하나로 지정한다. 음식 담당은 주방과 배식대를 오가며 실제 음식을 싣고 내리고, 정리 담당은 사용한 식탁에 가서 1.2초 동안 정리한다. 담당을 바꿀 때 이미 든 짐은 원래 진열대나 배식대에 먼저 내려놓고 새 일을 시작한다. 다만 정리 담당의 기존 납품처가 가득 차면 식탁을 먼저 정리하고, 빈자리가 생기면 든 짐을 내려놓는다. 음식이 가득한 배식대와 더러운 식탁 때문에 운영이 함께 멈추는 것을 막는다. 직접 지정한 담당은 연금 공방을 새로 열어도 유지한다. 고용 인원 상한 3명과 비용·공유 속도/운반 훈련은 유지한다.

식사 시간·기본 매출 24·단계별 보너스는 기존 여관에 연결한 원문 시설 수치를 재사용한다. 주방·배식대의 분리와 음식 운반·4개 식탁·조수 직무·정리 시간·착석·회복과 충성도 연결은 판타지 웹게임에서 새로 정했다. 원작 테이블 운영에 대한 사용자 설명과 이전 영상의 착석 고객 관찰을 참고했으며, 원작의 조리·정리 상수를 복원한 것은 아니다.

정리할 식탁이 여러 개면 가장 가까운 한 곳에 `정리` 표식을 표시한다. 다른 식탁도 바닥을 직접 눌러 이동할 수 있으며 가까이 멈추면 같은 방식으로 정리한다. 식사 중인 손님과 식탁 위 음식, 사용 후 빈 그릇을 장면 안에서 구분한다.

화면의 행동 버튼으로 플레이어·시설·조수 강화, 고용, 시설 개방, 순간이동, 일시 정지·재시작을 조작한다. PC에서는 화면 조작과 키보드 이동을 함께 제공한다. 자세한 화면별 안내는 게임 안 도움말을 기준으로 한다.

오른쪽 위 **메뉴 → 진행 초기화**로 새 상회를 시작한다. 시작 화면에서도 바로 초기화할 수 있으며, 확인 전 취소·닫기·Escape는 원래 화면으로 돌아간다. 확인하면 이 게임의 골드·강화·시설·조수·단골을 새 상태로 덮어쓴다. 다른 게임의 저장은 변경하지 않는다.

영업 카메라는 일정한 각도를 유지하며 플레이어를 따라간다. 상회 가장자리에서는 이동을 제한하고, 높은 짐이 상단에 닿으면 필요한 만큼 시야를 넓힌다. 순간이동·지역 이전·재시작·화면 크기 변경에는 구도를 즉시 맞춘다. 전투 카메라는 양 진영의 가까운 접점과 최근 공격 부근에서 가장 많은 인물이 싸우는 곳을 가까이 따라간다. 건물·입구·문 앞 주인공·멀리 대기하는 증원을 모두 담으려고 축소하지 않는다. 결과에서는 마지막 교전 구도를 유지하고 영업으로 돌아오면 기존 플레이어 추적 구도로 복귀한다. 모바일 작업장 표식은 52px 그림 버튼이며, 화면 밖 작업장은 테두리가 점선인 표식으로 안내한다.

전투 배율은 `min(60, 플레이 영역 폭 / 6.4, 플레이 영역 높이 / 6.5)` CSS px/world unit을 기준으로 고정한다. 인물이 흩어지거나 증원 수가 바뀌어도 확대율이 반복해서 변하지 않는다. 전투 전용 추적은 0.12 월드 단위 안의 작은 목표 흔들림을 무시하고 이동을 완화하며, 추적 속도를 초당 최대 5로 제한한다. 출전 페이드 안에서 첫 교전 구도를 맞추고 이후 실제 전선 이동을 따라간다. 이 수치와 추적 정책은 새 판타지 웹게임 설계다.

영업 시 가로 시야는 기본 9.4 월드 단위다. 일반 고객은 주인공의 동일 몸 모델 대비 72%, 조수 92%, 수호대 90% 크기로 표시한다. 적은 보병 95%·돌격/원거리 90%·정예 122%와 서로 다른 장식으로 구분한다. 실내는 18×18로 넓혀 양옆 생산·진열 시설과 뒤쪽 여관·주방·식탁을 떨어뜨렸다. 실제 모델 크기·높이·회전을 반영한 주요 시설 묶음 11개는 10개 지역 모두 바깥 윤곽 사이 최소 0.6 월드 단위 간격을 둔다. 이 비율·치수는 영상을 참고해 새로 정한 웹게임 값이다.

초반에는 실제 미결제 손님 12명까지 유입하고, 판매/시설 개방에 따라 최대 대기 24명·전체 30명까지 늘어난다. 상점 밖에는 최대 24자리의 공통 입구 줄이 있고 맨 앞 손님부터 0.55초 간격으로 입장한다. 입구 안의 분기점을 지난 뒤 구매 품목에 맞는 무기·물약 진열대 앞 6자리 줄로 향한다. 줄이 찬 품목의 손님이 맨 앞이면 자리가 날 때까지 입구에서 기다린다. 바닥의 갈림길과 대기 표식으로 이 흐름을 보여 주며, 줄은 인물을 막는 물리 장벽이 아니다.

첫 6명을 채울 때 최대 0.65초 간격으로 오며 이후 도착 간격은 `counter.seconds / (공방 개방 ? 2 : 1) × 0.75`를 0.3~1초로 제한한다. 빨라진 시설에도 줄이 이어지도록 수요를 늘린 것이며 원문 결제 시간·가격·생산 재고는 그대로 적용한다. 무기/물약 손님은 실제 물건을 사고 매출을 바닥에 남기며 구매 단골만 방어에 합류한다.

상품 줄이 가득 찼을 때 이미 뽑힌 손님의 직업을 다른 직업으로 다시 뽑지 않는다. 입장 가능한 자리가 생길 때까지 그 선택을 유지해 무기 줄 포화가 마법사 위주 유입으로 이어지지 않게 한다. 대기 목표는 최대 24명이지만 직업 선택과 상품별 16자리 제한에 따라 무재고 상태의 실제 대기는 20~24명일 수 있다.

주인공은 보라·아이보리, 일반 고객은 진한 파랑 의상·후드, 조수는 금색, 수호대는 청록, 적은 적색 계열로 구분한다. 직업 장식과 피부·얼굴·눈·무기는 유지한다. 실제 GLB 모델의 공유 atlas에서 옷·머리 덮개 영역만 로드 시 한 번 설정한 UV 셰이더로 바꾸며, 역할별 uniform과 같은 셰이더 프로그램을 쓴다. 원본 geometry·texture를 공유하고 색상 구분을 위한 메시·draw call을 추가하지 않는다.

모바일에서는 렌더 해상도 배율을 최대 1.25, 그림자 맵을 512px, 그림자 갱신을 최대 30회/초로 제한한다. 주인공 애니메이션은 렌더 프레임을 따르고 일반 손님은 최대 15회/초, 다른 화면 안 인물은 최대 30회/초로 갱신한다. 화면 밖 인물의 애니메이션은 생략하지만 이동·구매·전투 시뮬레이션은 유지한다. 직업 장식·스택 geometry를 공유하고, 체력바·직업 링은 두 인스턴스 묶음으로 그린다. 이 정책은 실제 휴대폰 자동 벤치마크 결과가 아닌 명시적인 모바일 렌더 예산이다.

전역 성장 21행의 운반량·이동 속도·가격 보너스·강화 비용을 보존한다. 일반 스테이지 10행과 이벤트 정의 1행, 직원 80명의 능력치, 등급 확률 4팩, 선택 시설의 비용·능력도 원문 수치를 유지한다. 표시 이름과 판타지 역할은 새로 만들었다.

현재는 플레이어 성장, 직원 추첨·원문 속도/운반량, 판매 기본값 5/24, 시설 1~3레벨의 비용과 첫 form 능력, 조수 공유 속도/운반 1~11레벨과 원문 훈련 비용을 실제 적용한다. 시설의 다른 form 선택, 스테이지 오프라인 보상 필드·별도 이벤트·직원 `income`의 별도 수익 효과는 아직 적용하지 않는다. 최고 플레이어 성장 행의 비용도 보존하지만 21레벨에서는 더 이상 비용을 지불하지 않는다. 시설·조수의 정확한 단계 매핑과 새 통화 해석은 `data/PROVENANCE.md`에 기록했다.

일반 지역 10곳은 이름뿐 아니라 바닥·장식·시설 위치·문과 동선이 다른 실제 맵이다. 방어 승리로 단계가 오르면 마당에서 결과를 보여 주고, `계속 영업`을 누르거나 규칙의 결과 대기 7초가 지난 뒤 다음 지역 상점으로 돌아온다. 결과 모달이 열린 브라우저에서는 시간이 멈춰 직접 계속을 누른다. 10곳 뒤에는 첫 지역부터 반복한다. 지도 목록에서는 아직 도달하지 않은 지역도 열람할 수 있지만 지역을 선택해 여행하거나 건너뛰는 기능은 없다. 이전 시 소지금·현금 더미·강화·보유 짐·단골을 유지한다. 별도 이벤트 야영지는 정의만 보존하며 플레이 지역으로 열지 않았다.

구매 단골 3명 이상을 확보해야 첫 습격이 시작된다. 판매 18회 또는 영업 90초 후 10초간 준비한다. 판매 8회 뒤 궁수와 연금 공방, 16회 뒤 여관, 20회와 공방 개방 뒤 마법사가 열린다. 시작 금화는 80이며, 이번 버전의 조수 동시 상한은 3명이다. 이동 21레벨에서 거리 3.5·대기 4초의 순간이동을 사용한다. 판매 금화 환산과 습격 보상·귀환 방어는 신규 웹게임 규칙으로 원문 비용과 분리했다. 정확한 계산과 조건은 `rules.mjs`, 보존·재해석 범위는 `data/PROVENANCE.md`를 참고한다.

10초 경고가 끝나면 영업과 시간이 멈춘 `마당 방어 준비` 확인창을 보여 준다. `마당으로 출전`을 누르면 2.2초 페이드가 진행되고 중간에 상점 내부 전체를 숨긴 채 건물 밖 마당과 수호대·적을 배치한다. 페이드 동안 이동·생산·판매·공격·피해는 진행하지 않으며, 전환이 끝나야 자동 전투를 시작한다. 야외는 실내 확장과 독립된 고정 좌표를 사용하고 상점 외벽·문·지붕·잔디·흙길·성벽만 보인다. 승리·패배 결과도 마당에서 유지하고, 계속하거나 무료 복구하면 상점으로 돌아온다.

침공은 단계와 최근 구매 단골 최대 18명에 따라 4~32명의 적을 편성하고, 처음 최대 14명이 함께 출현한 뒤 2.2초마다 3명씩 증원한다. 동시 생존 적은 최대 20명이다. 2단계부터 원거리와 정예가 섞이며 돌격병은 후열을 압박한다. 돌격병의 기본 속도는 1.95·사거리는 1.05, 적 궁병 사거리는 3.75다. 궁수·마법사 단골은 후퇴하는 동안 공격하지 않으므로 근접 압박에 대응하려면 앞줄 전사와 장비 성장이 필요하다. 적 체력·공격력·인원은 플레이어 장비·충성도에 맞춰 자동으로 올라가지 않는다. 더 높은 마법 부여 단계의 물건을 산 단골은 공격력·체력이 높고, 여관과 방어 승리의 충성도도 도움이 된다. 결과창에서 방어 시간·전투불능·부상·상회 피해를 확인한다. 전투는 원작에 없는 이 웹게임의 별도 설계다.

무기와 활·지팡이는 실제 모델의 오른손 뼈에 연결하고, 시뮬레이션에서 타격이 발생한 순번(`attackSerial`)이 바뀔 때만 약 0.45초 단발 모션을 재생한다. 공격 대상 쪽으로 몸을 돌리고 타격 후에는 걷기·대기 자세로 돌아간다. 이 연출로 원래 공격 간격·공격력·체력을 바꾸거나 피해를 중복 적용하지 않는다.

## 저장과 호환

저장 키는 `runehaven:v1`이며 이 게임의 데이터만 사용한다. 이번 확장도 v1을 유지하며 초기 v1 기록에 시설 단계·조수 공유 훈련·현금 더미 필드가 없으면 각각 1레벨·1레벨·0으로 보완한다. 선택 필드 `dining`이 없으면 주방 4그릇·배식대 0그릇·깨끗한 식탁 4개로 보완한다. 기존 식사 버전의 저장에 주방 값이 없으면 주방만 4로 채우고 배식대의 `food`는 그대로 보존한다. 플레이어·조수의 짐에 `food`가 없으면 0으로, 조수 담당이 없으면 기존 운반 품목으로 보완한다. 음식·담당·실제 운반 짐·정리 횟수·식탁 상태를 저장하며, 불러올 때 고객은 재생성하고 사용·예약 중 식탁은 정리가 필요한 상태로 바꾼다. 식사 중 재접속해 매출을 중복 지급하지 않는다. 기존 소지금과 구매·강화 기록은 유지한다. 신규 값이 범위를 벗어나거나 저장 구조가 손상되면 새 상회로 초기화한다. 다른 게임이나 원작 APK의 세이브는 읽지 않는다.

저장 공간 사용이 막히거나 저장에 실패해도 현재 탭의 기본 플레이를 유지한다. 처음부터 시작하면 이 게임의 새 기록으로 덮어쓴다. 출전·전투 중에는 야외 좌표 대신 출전 전 상점 위치와 실제 운반 짐을 저장한다. 이를 불러오면 구매·강화·짐·현금 더미를 유지한 상점의 45초 준비 상태로 돌아간다. 패배 상태를 불러와도 무료 복구 버튼을 제공한다. 저장 키와 버전은 `runehaven:v1`을 유지한다.

### 최신 전투 근접 추적 카메라 검증 — 2026-10-24

전투 중 상점 외벽과 모든 부대를 함께 담던 구도를 실제 교전 위치를 따라가는 근접 구도로 변경했다. 영업 카메라·전투 규칙·원문 수치·저장 형식은 유지한다. 아래 이전 146개 검증과 원거리 구도 화면은 이번 근접 추적의 검증 결과로 재사용하지 않는다.

지정한 16개 테스트 파일의 **152개가 모두 통과**했다(약 2.296초). 이 중 카메라 회귀는 20개로, 근접 교전 선택·먼 증원/사망자 배제·고정 확대율·전선 이동·원거리 전투·빈 진영·30/60Hz 추적을 확인한다. 변경한 `camera.mjs`와 `game.mjs`의 구문 검사 2개와 대상 `git diff --check`도 통과했다. 전투 규칙·저장·기존 식사와 조수 회귀를 함께 실행했으며 카메라 확대를 위해 전투 데이터를 변경하지 않았다.

데스크톱 브라우저의 **320×568**에서 실제 플레이 영역 320×338을 확인했다. 수정 전 전투 시야 span은 14.6162, 수호대의 실제 1.3×0.9 몸 투영 높이는 20.0405 CSS px이었다. 수정 후 같은 화면의 span은 6.76으로 고정되고 수호대 몸 높이는 **43.3308 CSS px, 약 2.16배**가 됐다. 이는 머리 장식·체력바를 포함한 높이가 아니라 실제 인물 몸 높이를 같은 기준으로 읽은 값이다. 근접 공격 클립과 타격 순번 1→6을 관찰하며 칼·도끼 동작을 확인했다.

전투 중 교전이 이동할 때 카메라 중심이 따라 움직이고 가까운 배율을 유지하는 것을 확인했다. 최종 소스로 다시 플레이한 320px 방어는 12.4777초·전투불능 4명·부상 8명·상회 피해 0으로 끝났다. 결과에서 플레이 영역 높이가 338→352, span이 6.76→7.04로 바뀌어도 마지막 중심 `(0.424812, 3.511945)`와 CSS 배율을 유지했다. 결과 화면에서 기본 PC 1280×720으로 복원했을 때도 플레이 영역 900×483·span 8.05와 같은 중심을 유지하고 가로 넘침은 없었다.
