# 수치의 출처와 재해석

`source-balance.mjs`는 사용자가 분석을 요청한 Burger Please 31.6.0(141), 패키지 `io.supercent.burgeridle`에서 확인한 수치 중 이 게임이 사용하는 부분만 담는다. 원본 APK, 원작 코드·장면·텍스처, 광고·인앱 결제 설정과 실제 플레이어 저장 데이터는 이 폴더에 포함하지 않는다.

## 그대로 가져온 수치

| 데이터 | 사용 범위 | 원문 테이블/직렬화 객체 |
| --- | --- | --- |
| 플레이어 성장 | 21행의 레벨·운반량·속도·가격 보너스·각 비용 | PlayerTotalUpgradeData_8 |
| 스테이지 | 일반 10행·이벤트 1행의 ID·재화 단위·오프라인 보상 관련 값 | StageData_37 |
| 직원 | 80명의 ID·등급·운반량·속도·수익·개방 스테이지 | StaffData_25 |
| 등급 확률 | 팩 4종×등급 4종 | StaffDrawProbabilityData_9 |
| 시설 | 첫 스테이지의 생산기 2종·카운터·테이블·고용 비용과 연결 능력 | StageObjectData_23 / StageObjectCostData_51 / StageObjectAbilityData_15 |
| 기본 가격 | 5와 24 | Stage_1_Burger_Price / Stage_1_BurgerPackage_Price가 참조하는 비용 표현 행 |
| 조수 성장 | 운반량·이동 속도·최대 고용 5·속도/운반/고용 비용·기존 자원 식별자 | WorkerData_Stage1 / WorkerUpgradeData_Stage1 |

원본 수치는 반올림하거나 비용 곡선을 재작성하지 않았다. 직렬화 float의 소수 표현도 그대로 보존한다. `provenance.json`은 원본 추출 파일명·SHA-256·원본 배열 인덱스·필드 이름과 직렬화 객체의 source/pathID를 기록한다. 런타임 모듈에는 조사용 출처 필드를 넣지 않았다.

## 이 웹게임에서 바꾼 의미

- 생산기 → 대장간/연금 공방, 카운터 → 잡화점, 테이블 → 여관, 고용 → 조수 길드로 바꿨다. 스테이지와 직원의 표시 이름은 판타지 이름으로 새로 붙였다.
- 원작에는 ItemType, ECostType, ECurrencyType 등 서로 다른 숫자 체계가 존재한다. 현재 시설 코드 1과 조수 훈련 코드 0·54의 선택 비용은 숫자를 그대로 두고 모두 웹게임 금화로 지불한다. 같은 숫자 코드를 원작의 특정 통화라고 단정하거나 현재 별도 룬 결제 자원이 있다고 설명하지 않는다.
- 원문 기본 가격 표현 값 5/24를 무기·포션·여관 서비스의 기본 가격으로 차용했다. 역할과 품목은 새 설계이며, 판매 금화 환산은 `balance.mjs`의 `WEB_RULES.saleCoinMultipliers`와 `rules.mjs`에서 적용한다. 판매·숙박 매출은 먼저 현금 더미에 쌓이고 플레이어가 회수한 뒤 소지금이 된다. 방어 보상은 즉시 소지금으로 지급한다.
- 원문 이동 속도 수치를 월드 이동 속도로, Delay 계열 값을 생산 시간(초)으로 해석한다. 원작 런타임 단위가 완전히 복원됐다는 뜻은 아니다.
- 21레벨 마지막 성장의 짧은 순간이동, 전사→궁수→마법사 손님 순서, 구매 손님의 귀환 방어, 몬스터/외적 습격, 전투 보상은 이 웹게임을 위해 새로 만든 규칙이다. 원작에서 추출한 기능이 아니다.
- 습격 보상과 판매 환산은 높은 원문 성장 비용을 모바일 한 판에서 경험하도록 추가한 별도 규칙이다. 원문 비용 숫자 자체는 변경하지 않았다.
- 웹 고용은 원문 확률 4팩과 직원 80명의 개방 조건·등급을 사용해 후보를 뽑고 능력치를 실제 조수에게 적용한다. 원작의 고용/가챠 호출 흐름을 복원했다고 주장하지 않는다. 이번 버전의 조수 동시 상한 3명은 원문 `workerMaxEmploy=5`와 분리된 새 규칙이다.
- 이동 마지막 강화의 순간이동은 거리 3.5, 대기 4초다. 일반 판매의 환산 배수 10·25·80·240·750·1500과 첫 습격 보상 3,000·8,000·24,000·72,000·216,000도 새 규칙이다. 원문 성장 비용과 속도/운반량은 그대로 유지한다.

## 이번 확장에서 실제 적용한 배열

시설은 1~3레벨의 **첫 form**에서 type 10을 생산/결제/숙박 초, type 30을 생산 재고 한도, type 20을 여관 매출 보너스 %로 해석한다. 대장간·연금 공방은 시간 `[3,2,1]`·적재량 `[4,10,14]`, 잡화점은 시간 `[2,1.5,0.9]`, 여관은 시간 `[5,4.7,3.7]`·보너스 `[0,0,5]%`를 사용한다. 숫자는 원문 그대로이며 웹에서의 단위·역할 적용은 해석이다. 다른 form은 보존하지만 선택·효과 전환 기능은 없다.

시설의 현재 레벨 `L`에서 다음 단계로 가는 비용은 원문 `costs[L]`다(0기반 배열). 따라서 대장간 120/1,990, 잡화점 100/1,750, 공방 330/2,090, 여관 370/1,200을 지불한다. `costs[0]`은 최초 개방 값으로 보존한다. 시작부터 열린 대장간/잡화점은 그 비용을 공제하지 않고 공방 230·여관 5만 개방 시 지불한다.

조수 공유 훈련 1~11레벨은 원문 수치를 직원 기본 능력에 합성한다. 속도는 `직원 원문 속도 × worker.speeds[L-1] / worker.speeds[0]`, 운반량은 `직원 원문 운반량 + worker.capacities[L-1] - worker.capacities[0]`다. 각 훈련 비용은 원문 `costs[L-1]`의 10개 값을 그대로 사용한다. 직원 `income`은 보존하지만 별도의 수익 배수로 적용하지 않는다.

## 새 조작·지역·저장 규칙

정지 임계 0.4초, 물건 하나당 상하차 간격 0.22초, 현금 접근 회수 거리 0.9는 사용자 요청을 반영한 신규 웹 규칙이다. 원작 영상의 정확한 상수를 복원한 것이 아니다. 머리 위 스택·공간에 남는 현금·카메라 구도 등 직접 확인한 원작 참고 근거와 미확정 관찰은 `../RESEARCH.md`에 분리한다.

일반 스테이지 10개의 원문 ID와 새 판타지 이름은 서로 다른 실제 웹 맵 배치에 연결했다. 지형·장식·시설/문 위치·동선은 새 제작물이며 원작 장면 복제가 아니다. 방어 승리 즉시 다음 지역으로 이전하고 10개 뒤에는 반복한다. 지도 목록 열람과 지역을 선택하는 자유 여행을 구분하며 후자는 구현하지 않았다.

스테이지의 오프라인 보상 필드와 이벤트 정의는 보존만 한다. 이벤트 야영지를 플레이 지역으로 열거나 원작 원격 설정을 적용하지 않는다. `runehaven:v1` 초기 저장은 새 필드가 없으면 시설/훈련 1레벨·현금 더미 0으로 보완하고 기존 재화·성장 기록을 유지한다.

## 라이선스와 한계

원작 추출 자료에 CC0 또는 오픈소스 라이선스가 있다고 주장하지 않는다. 이 문서는 출처 기록이며 이용 권한을 부여하는 문서가 아니다. 추가 이미지·모델·아이콘·글꼴은 게임의 `assets/SOURCES.md`에 각각 출처와 라이선스를 기록한다.

데이터는 APK에 포함된 기본값이다. 원작의 원격 설정·실험군·최신 스토어 버전·개인 세이브의 현재값을 뜻하지 않는다. 원본 추출 산출물은 저장소 밖 분석 폴더에서 유지하며 게임은 해당 폴더에 의존하지 않는다.
