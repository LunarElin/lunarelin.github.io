## 직접 관찰한 화면 요소

1. **운반 스택의 가시성:** 스토어 이미지 4의 빨간 유니폼 캐릭터는 몸 앞에서 머리 높이를 넘도록 버거를 수직으로 쌓아 운반한다. 이미지 3에서도 감자 운반물이 얼굴 앞에서 위로 길게 쌓여 있다. 운반량이 숨겨진 인벤토리 숫자만으로 표현되지 않는다는 점을 확인했다.
2. **생산·진열·운반 재고의 분리:** 이미지 4에는 생산기 토출대의 버거 스택, 카운터 위 높은 버거 스택, 캐릭터가 든 스택이 각각 따로 보인다. 이 관찰은 작업 공간 사이를 실제로 옮기는 표현의 근거다.
3. **현금의 공간적 적치:** 이미지 4의 카운터 옆에는 녹색 지폐 묶음이 바닥에 따로 쌓여 있다. 화면 오른쪽 위 소지금 HUD와 별도로 존재하는 더미를 직접 확인했다. 단, 이 한 장만으로 접촉 수거·자동 입금 여부를 확정하지 않는다.
4. **공식 영상 프레임:** 메인 에이전트의 약 5초 관찰에서는 드라이브스루 좌우 직원의 높은 운반 스택과 바닥 현금 더미가 보였고, 약 10초 패킹 구간에서는 손님 앞의 물건 이동이 보였다. 제자리 정지 입력 조건과 1개씩 반복 처리 간격은 이 프레임 보고만으로 확정하지 않는다.
5. **실제 플레이 기록의 보조 관찰:** 메인 에이전트가 0:35에서 생산기 앞 `MAX` 표시와 물건 2개를 든 캐릭터의 이동, 1:01에서 생산기·카운터의 높은 재고 스택과 테이블 옆 현금 더미, 1:11에서 이동하는 캐릭터와 남아 있는 바닥 현금을 직접 확인했다. 캐릭터가 매장 규모에 비해 크게 읽히고 카메라가 플레이어를 따라가는 구도도 관찰했다. 이는 룬빛 상회의 인물 크기·근접 작업 시야를 정하는 화면 참고이며, 원작 모든 기기의 카메라 수치를 복원한 것은 아니다.
6. **이전에 관찰한 5:12 구간의 고객 밀도·비율:** 메인 에이전트가 긴 파란색 고객 대기줄, 좌석에 앉은 고객들, 붉은 플레이어와 머리 위 적재물, 고객이 있어도 이동 경로가 남는 넓은 통로를 직접 관찰했다. 대기·착석·운반이 한 화면에 함께 읽히는 점을 참고했다. 영상 한 구간에서 원작의 전체 고객 상한이나 플레이어/고객 크기 비율을 계측한 것은 아니다.

## 확인하지 않은 동작과 추론

- **작업점에 서 있는 동안 1개씩 반복 상하차:** 정지 스크린샷에서 물건이 쌓이는 모습은 확인했지만, 정지 조건·개별 이동 순서·간격을 연속 영상으로 끝까지 검증하지 못했다. 사용자의 요구와 기존 APK 데이터의 운반량·Delay 구조를 반영해 구현할 수 있으나, 공식 영상을 관찰해 완전히 재현했다고 주장하지 않는다.
- **현금 직접 수거:** 바닥 현금 더미의 존재는 확인했다. 가까이 가야 소지금이 증가하는 정확한 트리거·수거 속도·재고 한도는 별도 연속 관찰 또는 실행 검증이 필요하다.
- **최신 버전과 일치:** 2023년 글·2024년 영상·현재 스토어 이미지의 시점이 다르다. 이 자료를 분석한 APK 31.6.0의 모든 규칙이 동일하다는 증거로 쓰지 않는다.
- **영상/이미지의 장식과 실제 규칙:** 스토어의 과장된 대형 재료/생산 장면은 핵심 상하차 동작의 근거로 차용하지 않는다. 화면에서 확인한 요소와 검증 가능한 선택 수치를 우선한다.

## 이번 수정의 구현 기준과 검증

사용자 요청에 따라 운반물을 캐릭터 머리 위까지 눈에 보이게 쌓고, 작업점에서 머무르면 개별 물건이 순서대로 올라오거나 내려가도록 연결한다. 판매 즉시 소지금에 더하는 대신 해당 매장의 현금 더미에 적립하고, 플레이어가 가까이 가서 직접 수거하도록 바꾼다. 숫자 HUD뿐 아니라 스택·개별 이동·수거 반응으로 상태를 읽을 수 있어야 한다.

정지 판정 **0.4초**는 사용자 요청을 반영해 정한 웹게임 값이다. 위 영상에서 추출한 원작의 정확한 임계 상수가 아니다. 개별 상하차 간격·수금 범위·캐릭터 크기 역시 새 구현값으로 구분한다. 웹 버전에는 원작 영상에서 관찰한 플레이어 추적과 크게 읽히는 인물을 적용했다. 짐 높이와 화면 여백에 따른 자동 줌, 가장자리 제한, 순간이동 시 구도 맞춤, 별도의 전투 근접 추적은 이 웹게임에 맞춰 설계한 기능이며 원작 카메라 수치를 복원한 결과가 아니다.

이전 관찰을 참고해 일반 손님의 렌더 배율을 주인공의 **0.72**로 정했다. **0.72는 원작에서 측정한 비율이 아니라 새 웹게임의 가독성 선택**이다. 시작 대기 목표 12명에서 시설 개방 후 최대 24명, 전체 고객 30명, 공통 입구 24자리와 진열대별 6자리, 여관 식사 희망 고객 4명도 새 운영 설계다. 18×18 매장과 영업 카메라의 화면 폭/9.4 기준 역시 원작 복원값으로 설명하지 않는다. 영상의 좌석 고객은 여관에서 앉아 먹는 표현의 참고이며 판타지 회복·충성도 규칙을 원작에서 확인한 것은 아니다.

사용자가 이동 중 겹침을 허용하고 빠른 이동을 원한다고 명시해 플레이어·조수의 이동은 직선으로 유지한다. 고객은 상점 밖 공통 입구 줄에서 FIFO 순서로 기다렸다가 0.55초 간격으로 한 명씩 입장하고, 문 안 분기점에서 구매 품목에 맞는 6자리 줄로 향한다. 진열대 앞 맨 자리는 `z + 0.95`, 다음 자리는 0.68 간격이며 공통 입구 줄은 문 `z + 0.6`부터 0.7 간격이다. 분기점은 `gate.z - 1.25`이고 바닥 선으로 안내한다. 이 입구·분기 규칙은 줄의 모양과 먼저 온 순서를 읽기 위한 새 설계다. 인물 충돌 회피·밀어내기를 다시 추가하지 않으며 원작에서 같은 알고리즘이나 간격을 계측한 것으로 설명하지 않는다.

주인공의 자동 납품 동선도 이 웹게임에서 정했다. 진열대 표식이나 가까운 바닥을 누르면 `getStationApproach`를 통해 진열대 뒤쪽 `station.z - 0.85`를 목표로 삼아 손님 앞줄과 구분한다. 공급기는 `station.z + 0.8`, 직접 조이스틱은 자유 이동을 유지한다. 모든 지역의 상품 대기 슬롯과 자동 납품 도착점 사이 거리 0.75 이상을 정적 검사 대상으로 둔다. 이 도착점은 원작에서 추출한 좌표가 아니다.

플레이어의 작업장·수금·식탁·바닥 탭과 조수 이동도 같은 직선 정책을 따른다. 조수는 플레이어와 동일한 작업 접근점을 공유하며, 줄 우회 경로·작업점 분산·경로 캐시를 사용하지 않는다. 현금 더미는 지역의 진열대 방향에 맞춰 중앙 쪽에 둔다. 전투의 기존 같은 편 분리 규칙은 유지하며 이번 영업 동선 단순화와 구분한다.

여관 식탁 운영은 사용자가 설명한 원작의 음식 수령·착석·퇴장 후 테이블 정리 구조와 이전 영상에서 확인한 좌석 고객을 바탕으로 추가했다. 이번 작업에서 원작 영상을 새로 재생해 청소 입력·시간까지 계측한 것은 아니다. 주방에 음식 4그릇을 준비하고 개방 후 3초마다 1그릇씩 최대 8그릇까지 조리하며, 새 게임의 배식대는 비워 둔다. 주인공이 주방 음식을 머리 위에 쌓아 직접 배식대에 내려놓고 음식 담당 조수도 같은 운반 작업을 수행한다. 무기·물약·음식은 공통 운반량을 나눠 쓴다. 식탁 4개, 구매 고객의 60%·최대 4명 배식 희망, 정리 시간 1.2초와 무기·물약·음식·정리의 조수 직무 지정은 새 운영 규칙이다. 주방·배식대 중심을 4 떨어뜨리고 주요 시설 묶음 사이 최소 0.6 간격을 둔 것도 모델의 실제 크기를 반영한 새 배치다.

기존에 여관에 연결한 원문 시설 시간 5 / 4.7 / 3.7초와 가격 24·단계별 보너스는 식사 시간·매출로 재해석한다. 음식과 깨끗한 식탁이 모두 있어야 배식하며 식사 완료 후 단골 회복·충성도 증가·대금 적치·더러운 그릇을 연결한다. 주인공이나 정리 담당 조수가 사용한 식탁을 정리한다. 기존 고용·훈련 비용과 직원 원문 속도·운반량은 유지하되 각 직무의 구체적인 동작은 판타지 웹게임에서 정했다. `dining.mjs`와 `rules.mjs`는 규칙을, `dining-visuals.mjs`는 기존 무료 가구와 공유 음식 모델의 표현을 맡는다.

색상 구분도 원작의 붉은 플레이어를 그대로 복제하는 대신 판타지 역할에 맞춰 새로 정했다. 기존 Mini Dungeon 아틀라스의 UV 띠를 셰이더에서 재사용해 주인공은 보라·아이보리, 고객은 파랑 의상·머리 덮개로 표시하고 피부·얼굴·눈 영역은 유지한다. 이 변경은 원본 텍스처와 모델을 다시 만들거나 색 구분용 메시를 추가하지 않는다. 체력바·역할 링은 기존 인스턴스 메시 두 개를 재사용한다. 중앙 보행 가이드는 각 지역 바닥과 조화되는 얇은 정적 box 두 줄이며 기존 바닥 무늬를 넓은 면으로 덮지 않는다. 실제 화면 가독성과 통합 검증 결과는 최종 [README](README.md)를 기준으로 한다.

대기열 외형 확인용 `?qa=1&scenario=queues`는 지역·판매 플래그 20·시설 개방·시설 3단계를 직접 지정한 인위적 검사 상태다. 실제 고객 이동을 45초 실행해 무재고 대기열 24명을 만들지만 단골·획득 매출은 0이고 금화는 시작값 80이다. 이는 정상 규칙으로 진행한 `late`·`late-defense`·`defense`·`defeat`와 구분하며, 원작 관찰이나 획득 진행의 근거로 사용하지 않는다. 지역 미리보기와 함께 일반 저장 읽기·쓰기를 비활성화한다.

후반 `late-defense`는 정상 생산·판매·수금·강화·승리로 6단계에 도달해 검사·궁수·마법사 단골과 정예·원거리 적의 전투를 재현하는 웹게임 검사 경로다. 시드 42의 규칙 재현과 이후 브라우저의 직접 전투 관찰은 구분하며, 실제 Burger Please!의 후반 전투나 전투 데이터로 설명하지 않는다. 궁수·마법사·정예 적과 흩어진 전선·마지막 적 추적은 이 판타지 게임의 별도 설계와 검증 범위다.

식사 외형용 `?qa=1&scenario=dining&previewRegion=N`은 대기열 검사 상태에 무기 12개·물약 8개·배식대 음식 4그릇을 지정한 뒤 실제 판매·배식·식사를 실행한다. 식사 중 손님과 사용 후 그릇이 함께 있는 장면을 재현하지만, 지정 재고·시설 개방을 획득 진행으로 취급하지 않는다. 주방에서 주인공이 나르는 새 음식은 지정한 배식대 재고와 구분해 검사한다. 두 검사 모두 `artificial:true`이며 원작의 동작을 검증하는 도구가 아니다.

시설은 원문 첫 form의 시간·적재량·단계별 비용을 생산·결제·식사 강화에 연결하고 조수 훈련도 원문 비용·수치 배열을 사용한다. 다만 시설 역할·통화 코드·시간 단위·단계 선택과 판타지 보너스 해석은 별도의 웹게임 규칙이다. 고객 밀도·역할별 크기·카메라·신규 방어 밸런스·메뉴 초기화 등 현재 설계는 [DESIGN](DESIGN.md)에 기록한다. 예전 테스트 수나 특정 차수의 패배 기록을 현재 보증으로 재사용하지 않으며, 최신 테스트 결과·브라우저 관찰·자체 평가와 미검증 실기기 항목은 [README](README.md)를 기준으로 한다.

후속 혼잡 플레이와 방어 난도 조정도 원작 복원과 구분한다. 무기 줄이 가득 찼다는 이유만으로 새 고객을 마법사로 바꾸지 않고, 먼저 뽑힌 직업이 입장할 자리를 기다리도록 했다. 전투에서는 원거리 단골의 후퇴 중 동시 공격을 막고 정예를 2단계부터 배치하며, 돌격병의 속도·사거리와 적 궁병 사거리를 조정했다. 적 체력·공격력·인원 계획·증원 시간과 보존한 원문 경제 수치는 바꾸지 않았다. 이 규칙은 판타지 상회의 전사·궁수·마법사 간 역할과 후열 압박을 만드는 신규 설계이며 Burger Please!에 같은 전투가 있다고 주장하지 않는다. 이번 수정에서 원작 영상을 새로 재생·계측하지 않았다.

실내가 갑자기 전투장으로 바뀌는 흐름은 10초 경고 뒤 일시 정지된 출전 확인창, 2.2초 페이드, 상점 밖 마당 전투, 결과 후 귀환으로 바꿨다. 전환 중에는 영업과 피해를 멈추고 내부 가구 전체를 숨긴다. 야외의 고정 좌표·상점 외벽·마당과 실제 손뼈 무기의 0.45초 단발 모션도 새 판타지 연출이다. 모션은 규칙에서 실제 타격이 발생한 순번·시각·목표를 따라가며, 원래 공격 스탯이나 피해를 모션이 바꾸지 않는다. 이 전장·손뼈 연출을 원작에서 추출한 장면이나 전투 데이터로 설명하지 않는다.

사용자가 전투 인물과 공격 동작이 작게 보인다고 지적해 전투 카메라를 실제 교전 위치를 따라가는 가까운 고정 배율로 바꿨다. 가까운 접점·최근 공격 부근의 밀집 교전을 고르고, 후반 원거리 교전에서는 실제 발사자와 피격 목표의 짝·머리와 무기 동작 여백을 함께 고려한다. 선택한 공격을 잠깐 유지하고 시점 교대에도 실제 렌더 위치의 최소 여백을 필요한 거리만 보정하는 방식은 이 웹게임의 화면 가독성을 위해 추가했다. 평소의 완화된 추적과 교대 순간의 최소 위치 보정을 구분하고 인물 크기를 유지한다. 건물·입구·문 앞 주인공·먼 증원은 확대율의 기준에서 제외한다. `min(60, 플레이 영역 폭 / 6.4, 플레이 영역 높이 / 6.5)` CSS px/world unit과 작은 추적 흔들림 제한은 새 설계값이다. 공격력·체력·증원 규칙과 원문 경제 데이터를 바꾸지 않으며, 이 추적 알고리즘이나 수치를 원작에서 측정했다고 주장하지 않는다.
