# 카드 게임 스킬 기준 검토

2026-10-28 중간 검토 기록. 사용자 요청으로 `card-game` 스킬과 효과 처리 참고 문서를 적용했다. 기존 HTML/CSS/ES 모듈·Node 테스트·GitHub Pages 구성을 유지한다. **당시에는 로컬 검토 단계였으며, 후속 UI·아트 작업에서 내부 브라우저 검증을 진행했다.** 최신 상태와 평가는 [UI-ART-UPDATE.md](UI-ART-UPDATE.md)를 참고한다.

## 검토 결론과 변경

카드 데이터와 실행 인스턴스가 분리되어 있고, 카드 ID가 같아도 UID로 구분한다. 전용 RNG의 상태가 저장되며 Fisher–Yates로 섞는다. 실제 카드는 draw/discard 중 한 곳에 존재하고 화면의 사용 카드 표시는 별도 읽기 정보다. 양측은 같은 카드·충전·효과 처리기를 사용한다. 이 구조에서 재현 가능한 진행 불가 버그는 발견하지 못했다.

덱을 준비할 때 자원 곡선을 읽기 어렵다는 개선점을 반영했다. 기존 **연계** 창을 **덱 분석**으로 확장하여 아래를 표시한다. 통계를 읽는 작업은 카드·기력·셔플·RNG·저장을 변경하지 않는다.

- 비용 0/1/2/3 이상별 실제 카드 장수와 평균 비용. 같은 카드의 여러 장도 각각 계산한다.
- 공격·보호막·회복·기력 공급·선충전의 보유 장수. 카드 종류 이름 대신 실제 효과를 보므로 서리 발톱은 공격과 보호막에, 달빛 샘은 회복과 기력 공급에 함께 포함된다.
- 기력 공급과 다음 카드의 빈 충전 칸을 채우는 선충전을 구별한다. 선충전만 하는 야생의 신호를 기력 공급 카드로 세지 않는다.
- 앞장·뒷장 카드와 강화 등급, 상대 덱 장수에 따른 선공. 동률 선공은 실제 전투와 같이 플레이어다.
- 기존 변신·연계 안내를 유지하고, 추천 카드 보유가 발동 순서를 보장하지 않는다는 설명을 추가했다. 스크롤 중에도 닫을 수 있는 상단 버튼을 추가했다.

사용 전 카드 설명의 오류도 수정했다. 충전이 부족한 카드까지 접근성 이름에 “자동 발동”이라고 나왔다. 이제 **사용 준비 / 충전 부족·버림 예정 / 자동 발동 / 충전 부족으로 버림**을 구별한다. 양측에 동일하게 적용하며 화면의 큰 카드·타격 타이밍은 유지한다.

규칙을 변경하는 대신 [README의 효과 처리 순서](README.md#효과-처리-순서)에 고정 순서와 사망 직후 후속 효과 정책을 명시했다. 사용 중인 카드의 후속 폭발·회복은 마저 처리하고, 반격은 양측 생존 시에만 나오며 죽은 시전자를 폭발 회복으로 되살리지 않는다. 수동 손패·드래그 사용·타깃 선택·범용 효과 스택은 도입하지 않았다. 저장 키와 v4→v5 이전은 그대로다.

## 확인한 검증

```powershell
node --check games/wild-oath/game.mjs
node --check games/wild-oath/combat-presentation.mjs
node --check games/wild-oath/deck-analysis.mjs
node --test games/wild-oath/tests/rules.test.mjs games/wild-oath/tests/combat-presentation.test.mjs games/wild-oath/tests/deck-analysis.test.mjs games/wild-oath/tests/card-integrity.test.mjs
git diff --check -- games/wild-oath
```

**67/67 통과**. 기존 57개에서 아래 10개를 추가했다.

- 덱 분석 5개: 비용별 장수·평균, 실제 효과별 역할, 기력 공급/선충전 구별, 정렬된 인스턴스와 등급, 비변경성·실제 선공 일치·빈 덱 경계.
- 카드 보존 4개: 같은 ID의 서로 다른 UID, 자연 탐험 6개(seed 1/2/3/7/19/41)의 매 행동에서 원본 덱과 양측 구역 일치, 중복·누락·불법 충전 저장 거부, 부분 충전→재섞기→부족분만 결제와 복원 후 다음 이벤트·전체 상태 일치.
- 사용 전 설명 1개: 양측의 실제 성공/충전 실패 이벤트를 사용해 준비와 처리 완료의 설명을 구별.

새 카드·밸런스·규칙 수치가 바뀌지 않아 100시드 밸런스 비교는 반복하지 않았다. 이전 실제 UI 플레이 결과는 [기존 검증 기록](VERIFICATION.md), [타격 연출 검증](COMBAT-FEEDBACK.md)에 있으며 이번 새 화면의 실행 근거로 간주하지 않는다.

## 화면 검증 중단과 남은 작업

아래는 중간 검토 시점의 제한이다. 후속 작업에서는 Codex 내부 브라우저로 새 창·카드 상세 복귀·320/390px 세로·844px 가로·실제 전투와 재시작을 검증했다. Chrome 제어는 사용하지 않았다. 후속 검증의 수치·범위는 [UI·아트 검증 기록](UI-ART-UPDATE.md)에 구분했다.

브라우저 자동화 연결이 동작하지 않아 Windows Computer Use로 Chrome 검증을 시도했다. 이 도구가 **현재 브라우저 URL을 정책에 필요한 신뢰도로 확인하지 못했다**고 보고하며 이번 턴의 UI 제어를 중단했다. 그 뒤 UI 입력·우회 도구·화면 상태 주입은 사용하지 않았다.

따라서 새 덱 분석의 실제 렌더링·모바일 320~390px 줄바꿈/터치 영역·닫기/복귀·게임 완주를 이번 변경으로 검증하지 못했다. 스크린샷이나 실제 플레이 성공을 주장하지 않으며 배포를 보류한다. 재연결 뒤 아래를 먼저 확인한다.

1. PC와 320×568/390×640에서 덱 분석 열기·스크롤·고정 닫기 버튼·본문/수치 가독성·가로 넘침을 확인한다.
2. 구매·덱 편입/제외·일괄 합성·앞장/뒷장 지정 후 분석이 현재 덱을 반영하는지 확인한다.
3. 실제 충전 실패의 사용 전/후 설명과 정지·재개·새로고침을 확인하고 한 여정을 플레이한다. 확인한 결함을 고친 뒤 커밋·배포·공개 반영을 검증한다.
