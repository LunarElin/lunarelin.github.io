# UI·아트 개선과 내부 브라우저 검증

2026-10-28. `game-ui-ux`·`create-game-assets`·내장 `imagegen`을 적용했다. 이전 카드 게임 스킬 검토의 덱 분석과 회귀 테스트도 이번 업데이트에 포함한다. **화면 조작·검증은 Codex 내부 브라우저(IAB)에서만 진행했고 Chrome 제어는 사용하지 않았다.**

## 결과

- 덱 분석에 비용 분포·평균 기력·실제 역할별 장수·정렬 표식·선공을 표시한다. 한 카드가 보호막·공격 등 여러 역할을 가질 수 있으며 기력 공급과 선충전을 구별한다.
- 분석 위에 카드 상세를 열고 닫으면 분석으로 돌아온다. 정렬·편입·제외·강화 뒤 분석을 다시 계산하고 닫기 버튼으로 포커스를 돌린다. 상세를 열 때 분석 위치를 버리지 않는다.
- 크림·이끼색·황금색의 테두리와 접촉 그림자를 통일하고 배경 도트의 밝기·빈도를 낮췄다. 민트/코랄 진영 구분과 기존 버튼 배치는 유지한다.
- 일반 카드에 액션 삽화 12종을 적용했다. 같은 카드는 선택·덱·상점·보상·도감·비행·전투에서 같은 그림을 사용한다. 변신 카드와 캐릭터 초상화는 기존 형태 그림을 사용한다.
- 작은 세로·가로 전투의 일반 카드 그림 높이를19~28px에서30px로 확보했다. 숫자·설명·충전 표시가 우선하며 모션·규칙·밸런스·저장 버전은 바꾸지 않았다.
- 사용 전 카드의 접근성 설명은 준비/충전 부족·버림 예정과 실제 사용/버림 결과를 구별한다.

새 삽화는 불투명 320×160 WebP 12개, **총153,470 bytes**다. 기존 캐릭터를 참조한 생성 원본 한 장을 정규 격자로 분리·중앙 crop·압축했다. 거대한 원본은 배포하지 않는다. [아트 기준](assets/art-direction-brief.md), [전체 프롬프트·출처](assets/cards-v2/ART.md), [파일 manifest](assets/cards-v2/manifest.json), [카드 매핑](card-art.mjs)을 보관한다.

## 구현 중 발견·수정한 문제

모바일 카드 선택의 기존 아틀라스 배율 규칙이 새 그림의 `cover`보다 우선하여 확대·왜곡되는 문제를 수정했다. 승리 보상의 옛 썸네일도 같은 액션 삽화로 연결했다. 분석→카드 상세→닫기에서 야영지로 바로 빠지던 흐름을 모달 중첩으로 바꾸고 현재 분석에 복귀하도록 했다.

코드의 역할은 기존과 같다. `rules.mjs`가 상태·셔플·자원을 처리하고 `game.mjs`가 입력·DOM·정지/재개·저장을 연결한다. 분석은 `deck-analysis.mjs`의 읽기 연산이며 새 이미지는 `card-art.mjs/css`에서 선택한다. 추가 프레임 루프·설치 의존성·공통 엔진은 없다. 기존 AbortController·페이지 이탈·탭 숨김·오디오 정리 경로를 사용한다.

변경된 진입 모듈·연출 헬퍼·연계 CSS에는 같은 버전 쿼리를 붙였다. 재방문자의 캐시에 이전 모듈이 남아 새 export나 분석 스타일이 섞이는 경우를 줄인다.

**69/69 통과.** 기존 규칙·연출, 새 덱 분석, UID 보존·부분 충전·재섞기·복원 후 다음 행동 일치에 더해 28종×3등급의 그림 매핑·12개 파일의 존재·WebP 헤더·크기 기록·SHA-256·200KB 예산을 확인했다. 실제 파일 크기와 시각 crop은 별도의 이미지 검사 및 접촉 시트로 확인했다. HTML ID 중복·분석 DOM 연결·닫기 버튼·문서 링크도 정적 검사했다. 규칙 수치는 바뀌지 않아 형태별 100시드 밸런스 비교는 반복하지 않았다.

## Codex 내부 브라우저 확인

실제 UI 버튼으로 조작했다. localhost의 검증용 진행을 사용했고 사용자 진행·승패·HP·카드 풀을 주입하지 않았다. 기록 원본은 [ui-art-browser.json](tests/ui-art-browser.json)이다. 데스크톱의 모바일 뷰포트 검증이며 실제 iOS/Android 기기 검증과 구분한다.

두 검증 여정을 구분한다.

1. 이전 UI 테스트의 2시련 탐험을 이어갔다. 구매·합성·정렬·편입/제외를 거쳐 **2시련 승리 직후 생명9**를 확인했다. 이후 가시덤불과 추가 정비를 거쳐 **3시련에서 패배**, 종료 창2/5·총피해209와 새 덱 재시작을 확인했다. 실패를 완주로 기록하지 않는다.
2. 새 여정의 무작위8장 선택→탐험→정비→선두 늑대→전투를 진행했다. 사용 전 “사용 준비” 설명을 실제로 읽었다. 정지·새로고침 전후 생명70/70, 내 덱7/버림1·상대 덱8/버림0이 보존됐다. 재개 뒤 **첫 시련 승리 생명45**, 보상과 홈페이지 왕복 뒤 다음 탐험·생명63·골드19·덱9장이 보존됐다.

새 보상 그림·도감 검색·이벤트 획득·일괄 합성·패배·재시작·홈 왕복을 실제 UI로 확인했다. 콘솔 경고/오류는0이었다. 충전 실패의 짧은 사용 전 프레임은 이번 실전에서 포착하지 못했으며 양측 설명 회귀 테스트의 근거로 구분한다.
